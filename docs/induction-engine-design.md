# 状态机归纳引擎：设计

> 2026-09-11 · Longquan 龙泉 · 从「打地鼠」到「会学」的第一块引擎
> 前提：真高山是「结构归纳」，但 ARC-AGI-3 的题是**交互状态机**，不是网格变换。
> 所以程序合成要改造成「状态机归纳」，对象从「原语序列」换成「隐藏状态的转移规则」。

---

## 0. 一句话

龙泉卡在 ls20 L4，不是卡在「没努力」，是卡在「门什么时候开（gate_u 翻转）」这条规则，
**落在人肉逆向的观测半径之外**。状态机归纳引擎做一件事：

> 把每一次探针实验，从「NO_CLEAR + 一堆坐标」这种**垃圾输出**，
> 变成一条**结构化证据**（状态 S → 动作 A → 状态 S'），
> 喂给一个「最短规则优先 + 证据淘汰」的归纳器，
> 让它自己搜出「门什么时候开」。

「会学」的判据不是「又通了一关」，而是「归纳过程可审计、假设空间可收敛」。

---

## 1. 三个量：证据、规则、归纳器

### 1.1 证据（Evidence / Transition）

一次探针实验产生一串帧，每帧可编码成一组**可观测特征**。从 ls20 探针日志里已提炼出这些特征（都是程序从渲染平面闭卷读到的，不是读源码）：

| 特征 | 类型 | 含义 |
|------|------|------|
| `gate_u` | bool | 门是否解锁（目标变量） |
| `armed_only` | set[(x,y)] | armed-only 格集合 |
| `unlocked_stamp` | bool | stamp 是否已解锁 |
| `has_plus` | bool | 是否有 plus 可搬 |
| `ui` | int | 能量/步数条 |
| `levels` | int | 关卡 |
| `cursor` | (x,y) | 光标位置 |
| `mover` | (x0,y0,x1,y1) | 移动对象包围盒 |
| `stamp_c9` | int | 计数器 c9 |

一条证据 = `(S_before, action, S_after)`，其中 S 是上面特征的取值，action ∈ {UP, DOWN, LEFT, RIGHT, STAMP, PICKUP}。

**关键**：证据不是探针脚本 print 的 debug 字符串，是一个数据类。现在 60 个探针的产出全是字符串，这是「打地鼠」和「会学」的分水岭——证据要能进归纳器。

### 1.2 规则（Rule）

规则是「门什么时候开」的一个候选假设，形式是**合取规则列表**：

```
Rule = [
    Condition(feature="armed_only", op="非空"),
    Condition(feature="ui", op=">", value=10),
    Condition(feature="unlocked_stamp", op="==", value=True),
]  → 预测 gate_u 会翻转
```

**为什么用规则列表而不是神经网络/决策树库**：

1. **天然有 MDL 复杂度**：规则越短（条件越少、每个条件越简单），复杂度越低。
2. **天然可审计**：每条规则是一句人话，归纳轨迹能打印出来给人看。
3. **天然对应「原语」**：一个条件 ≈ 一个可解释的原语，规则 ≈ 原语的组合——这正是龙泉「原语 + 组合」的思想，只是原语从几何变换换成了状态谓词。

### 1.3 归纳器（Inducer）

按 MDL 从短到长枚举规则，用证据淘汰：

```
for rule in enumerate_rules(复杂度从小到大):
    if 任何证据否证 rule:   # 规则预测翻转但实际没翻，或反之
        记录「rule 被证据 X 否证」  → 淘汰
    elif rule 与所有证据一致:
        返回 rule   # 这是最短的一致规则
```

「最短的一致规则」= 当前证据集下后验最高的假设（奥卡姆剃刀）。**它不保证是真规则**——这正是 the-real-mountain.md 里「最优是相对的」的诚实边界。但它是「可审计的、能收敛的」最优，不是「我猜的」。

## 2. 最小闭环（第一版只做这个）

第一版不追求「自动发现隐藏 c 寄存器」，收敛到**一个能跑通的最小闭环**：

```
探针实验 → 结构化证据（Transition 列表）
        → 归纳器（MDL 最短优先 + 证据淘汰）
        → 输出「gate_u 翻转规则」+ 可审计的归纳轨迹
```

**不在第一版范围**（诚实标注，避免滑回过度设计）：

- 不自动发明新特征（用已提炼的 9 个特征）
- 不做「动作序列规划」（那是搜索器的事，引擎只归纳规则）
- 不做跨游戏迁移（先在一个游戏里跑通）

---

## 3. 验收：三样证据（把「会学」从口号变判定）

沿用 roadmap 站 3 的验收哲学，落到状态机归纳：

1. **归纳轨迹可审计**：打印「按什么顺序试了哪些规则、每条规则被哪条证据否证、假设空间怎么缩小」。
2. **失败证据驱动收敛**：记录「在状态 S 预测 gate_u 翻转，实际未翻转」，且这条证据淘汰了哪些候选规则。
3. **跨关复用（第二版）**：从 ls20 L1–L3 归纳出的规则，能否作为 L4 的规则先验，而不是 L4 从头猜。

**第一版的验收，就是第 1、2 条。第 3 条是「反向验证引擎」那一步的验收。**

---

## 4. 反向验证（引擎对不对的试金石）

用已 WIN 的关，把「人肉已逆向出的规则」当标准答案，问引擎：

> 引擎能从这些关的观测证据里，自动归纳出同一条规则吗？

- **归纳得出** → 引擎抽象够用，可以放它去攻 L4。
- **归纳不出** → 说明引擎的特征/规则空间有缺口，这个缺口**恰好就是 L4 卡住的原因**。

ls20 L3 已知的「通用解锁规则」是现成的标准答案：

> `armed-only 非 gate 且 y<54 的格 = 解锁对象；进入它后重跑两阶段流程`

第一版引擎的第一个反向验证目标，就是：**从 L3 的观测证据里，自动归纳出「armed-only 非空 → 可解锁」这条规则。**

## 5. 与现有架构的关系

引擎**不是**另起炉灶，是接在 `interactive/` 之上：

```
selector.py（族路由）──→ interactive/ls20, maskflip, m0r0（各自 seated clear）
                                    ↑
        induction/（本引擎）← 把 tools/*_probe.py 的手写逻辑，升级成归纳器
```

- `tools/` 下的探针脚本**保留**，但它们的产出从「字符串」改成「结构化 Transition」。
- 引擎读 Transition，归纳规则；规则反哺探针的下一步动作。
- 第一步落点：`longquan/induction/`，纯离线、纯 Python，先跑通逻辑，再接真引擎。

---

## 6. 诚实边界（三条红线延续）

1. 引擎从**渲染平面**读特征（闭卷），不读引擎源码。
2. 引擎输出的是「最短的一致规则」，**不宣称是真规则**——最优是相对的。
3. 归纳不出「真规则」不是引擎的失败，是「抽象不够」的信号——反向验证就是要暴露这个缺口。
