## 二、动作空间（关键）

- `available_actions = [6]` —— **只有 ACTION6 一个动作**。
- `action_input = {"data": {}, "id": 0}` —— 空 data。
- ACTION6 不带坐标 → HTTP 500；**带像素坐标 (x,y) → 200**。
- 语义（实测）：**点击 color9 块 → 该块翻转为 color8**（9→8）。
- 点击 color8 / color0 / color2 / color5 → 帧不变（无效）。

| 探测 | 结果 |
|------|------|
| ACTION6 (36,36) 点 color9 | 38px 从 9→8（翻转） |
| ACTION6 点 color8 | 帧不变 |
| ACTION6 点 color0/2/5 | 帧不变 |

**判读**：ft09 是"点击翻转"型网格游戏——把正确的 color9 块翻成 color8，直到匹配
目标图案。这是**交互式网格操作**，不是"移动体走到目标"。

## 三、是否超出原语库（核心判断）

当前原语库（ls20 验证过的）：**move（方向移动）、match（盖印）、reflect（反射）**。

**ft09 明显超出**，理由：

1. **动作空间不同**：ls20 = ACTION1-4 方向移动；ft09 = ACTION6 坐标点击。
   没有"移动体"，没有 walkable，`locate_mover` / `build_walkable` / `energy_bfs`
   整套框架**不适用**。
2. **机制不同**：ls20 = "移动体→目标→盖印"；ft09 = "点击→翻转 9↔8→匹配图案"。
3. **无 ls20 的复杂交互**：没有燃料、传送门、补给、环、武装前置。

**但有一个正向信号**：ft09 是**纯静态网格 + 点击**，规则比 ls20 更"干净"，反而更
接近路线规划里的**经典几何原语族**（translate/recolor/copy/镜像）。画面里左右/上下
有明显的 9-8-9 对称图案，疑似**镜像/复制**任务——这正是 reflect 原语的潜在领地。

## 四、战略判断（供决策：继续 ls20 vs 转 ft09）

| 维度 | ls20 | ft09 |
|------|------|------|
| 机制 | move+match（已通关 L1-L3，L4 卡） | 点击翻转（未通关） |
| 动作空间 | 方向移动 | 坐标点击 |
| 与现原语库距离 | 已覆盖 L1-L3 | 需新原语（翻转/点击） |
| 规则复杂度 | 高（燃料/传送门/武装前置） | 待探（表面更简单） |

**建议**：ft09 是**终极验收目标**（roadmap 终点），且探路成本极低。它需要的是
"网格点击翻转"新原语 + "图案匹配"——这与 ls20 的 move+match 是**两条独立线索**。

如果目标是"通关 ls20 全部 7 关"（熟练当前原语），继续 ls20；如果目标是"冲刺
终极验收"（ft09 正分），现在转向 ft09 更符合 roadmap 的终局指向。两者不冲突，但
**时间只能投一个**。
