# 龙泉开发纪律（防走错、防走偏）

> 2026-09-06 · 推进核 · 面向：公司开发团队
> 这不是新规则，是把散落的红线 + 已经发生过的「走错走偏」浓缩成一份自检清单。
> 关联：`dev-task-spec.md`（任务分派）、`verify-games.md`（游戏→原语结论）、`methodology.md`（为什么）

---

## 0. 一句话

龙泉的命门是「闭卷会学」。纪律不是限制你，是防止你把「会学」一步步做成「背题」而不自知。下面每条，都对应一次真实发生过的走错或走偏。

---

## 1. 三条红线（不可破，违者验收不通过）

1. **不背题**：求解器代码里不得出现「某关卡 = 某动作序列」；不得 import 罐头表。
2. **不读源码（运行时）**：运行时只能吃帧；读引擎源码只发生在 design-time 探路，且结论只能用来「理解规则」，不能变成硬编码答案。
3. **不以「像素看起来对」当通过**：通关以「线上 / 回放 levels 递增」为准。

---

## 2. 认知活 vs 体力活：越界就是走错

团队只做「体力活」——实现推进核定好的接口、写测试、按给定验证游戏验证。

以下认知活**不要自己做**，拿不准就先问推进核：

- 判断「这个游戏的真实规则是什么」（游戏 → 原语映射）
- 定义 / 修改原语接口语义（几何三件套 / 交互五件套）
- 精确化 `WorldState` 字段、`action` 类型
- 原语库「求全」的论证

**为什么**：三次误判（recolor→m0r0、translate→vc33、copy→ls20）都栽在「看到表面线索就下结论」。判断规则是推进核已经想清楚的部分，不要重新想。

---

## 3. 探路脚本 vs 求解器：最容易滑向背题的一条

仓库里有两类代码，边界是铁的：

| | 探路脚本 | 求解器 |
|---|---|---|
| 位置 | `tools/_probe_*.py`、`tools/_reproduce_*.py` | `longquan/` 下的 step / search / plan |
| 性质 | design-time 人肉发动作、看帧、复现行为 | runtime 从帧 + 原语推导 |
| 能否硬编码动作序列 | **可以**（那是人肉探路） | **绝不可以** |
| 目的 | 搞懂规则 | 闭卷求解 |

铁律：

1. **求解器不得 import 探路脚本。**
2. **探路脚本里硬编码的动作序列，严禁复制进求解器。** 探路得到的规则要「抽象成原语 / 转移」再进求解器，不是「把试出来的动作序列贴进去」。

**为什么**：探路脚本里那些 `seq = [1, 2, 2, ...]` 是合法的「人肉试错」；但它们一旦进入求解器，就从「探路」变成了「罐头」，红线 1 破。

---

## 4. 口径一致性：用最新版，清残留

口径曾多次翻转，以 `docs/verify-games.md`（第三版）和 `docs/STATUS.md` 最新版为唯一准绳：

- ls20 = move + match，**不是 copy**。
- copy / recolor / translate 三原语撤回「未验证」。
- 色 11 是步数进度条 UI，不是目标；色 0/1 是静止目标标记。
- `perceive.py` 是 AR25 特化，不能硬套别的游戏。

动手前先看最新口径；发现代码 / 注释里残留旧说法（copy→ls20 之类），顺手修正或上报，不要让它继续传播。

---

## 5. 验收：离线通过是必要非充分

1. 单元测试离线跑通——必要，但不够。
2. 真实验证：线上实测 levels 递增，或本地 arcengine 回放 levels 递增。
3. 不硬凑验证游戏：没有真实验证游戏的原语，标「未验证」，不造假。

**为什么**：「回放是对过去的真理，不是对未来的真理。」离线全绿只能证明「自洽」，不能证明「会了」。

---

## 6. 提交前自检清单（每一条打勾再交）

- [ ] 求解器代码里没有任何硬编码的动作数字序列？
- [ ] 没有 import 探路脚本、罐头表、引擎源码？
- [ ] 我的验证是「levels 递增」实测，不是「看起来对了」？
- [ ] 我用的口径是 verify-games.md 第三版，不是旧说法？
- [ ] 我没有自己拍板「这个游戏是什么规则」？

---

## 7. 一句话

**走错 = 把交互游戏当几何变换；走偏 = 把探路答案写进求解器。** 守住「认知边界 + 探路/求解器铁律 + 口径一致」，就守住了龙泉是「会学」不是「背题」。
