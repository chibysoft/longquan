# 龙泉原语全集（Taxonomy）：求全，而不是拍脑袋

> 2026-09-05 · Longquan 龙泉 · 这是 primitives.md 的「全集」补充
> 核心判断：**原语库不全，选择器就选不出对的原语，L2 就是空谈。**

---

## 0. 为什么「求全」是命门

选择器面对新游戏，做的是「在原语库里挑一个能解释观测的原语」。如果真规则的原语不在库里，选择器无论多聪明都选不对——它只能在错误的候选里硬选。

所以「全」不是 nice-to-have，是 L2 成立的必要条件。

但「全」有个陷阱：**不能靠「枚举 ARC 25 款游戏」来求全**（那是背题），要靠「从 ARC 的设计原理出发，推出原语的全集」——因为原语是对应「人类视觉认知的基本操作」，这个集合是有限的、可从原理推出的。

---

## 1. 原语全集的分层（从设计原理推出）

ARC 测的核心是「用少量例子归纳出人类视觉概念」。人类视觉概念的基本操作，分五族：

### A 族：几何变换（对象在空间里怎么变）

| 原语 | 做什么 | 自由参数 |
|------|--------|----------|
| translate 平移 | 对象整体位移 | (dx, dy) |
| rotate 旋转 | 对象旋转 90° 的倍数 | 角度 0/90/180/270 |
| reflect 反射 | 对象关于轴镜像 | 轴位置 + 方向 |
| scale 缩放 | 对象放大/缩小 | 倍数 |
| shear 错切 | 对象斜切变形 | 切变系数 |

### B 族：拓扑/组合（对象之间怎么关系）

| 原语 | 做什么 | 自由参数 |
|------|--------|----------|
| copy 复制 | 对象复制若干份 | 份数 + 偏移 |
| connect 连接 | 对象/线之间连线 | 连线方向 |
| fill 填充 | 封闭区域填色 | 填充色 |
| contain 包含 | 判断包含关系并作用 | 规则 |
| overlap 交叠 | 对象交叠的并/交/差 | 操作类型 |

### C 族：颜色/数值（颜色和计数怎么变）

| 原语 | 做什么 | 自由参数 |
|------|--------|----------|
| recolor 颜色映射 | 颜色按映射表变换 | 映射表 |
| count 计数映射 | 数量→颜色/形状映射 | 映射表 |
| order 排序 | 按某维排序重排 | 排序键 |

### D 族：对称/模式（规则本身的结构）

| 原语 | 做什么 | 自由参数 |
|------|--------|----------|
| symmetry 对称补全 | 根据对称轴补全缺失部分 | 轴类型 |
| tiling 平铺 | 用小块铺满区域 | 块大小 |
| pattern 模式重复 | 按周期重复某模式 | 周期 |

### E 族：物理/交互（引擎状态机，2026-09-05 探路后新增）

> 关键转折：ARC-AGI-3 的「游戏」是**实时交互引擎**，不是经典 ARC 的「网格变换题」。源码逆向 + 线上实测证明，多数游戏的主导机制落在前四族之外。这一族是探路后补上的，不是拍脑袋加的。

| 原语 | 做什么 | 自由参数 | 探路实证 |
|------|--------|----------|----------|
| move 移动 | 对象在按键/力下逐步位移 | 方向 + 步数 | m0r0、g50t、cd82、ls20 |
| mate 配对 | 同色/同类对象重合后消除 | 配对判据 | m0r0 |
| match 匹配 | 对象与目标的集合/像素匹配判定 | 匹配规则 | r11l、tr87、ls20 |
| sequence 序列 | 按序变换/排序对象 | 序列规则 | tr87 |
| gravity 重力 | 对象沿某方向持续物理位移 | 方向向量 | vc33 |
| waypoint 路径点 | 对象跟随路径点质心/路由 | 路径点集合 | r11l |
| toggle 点击翻转 | 点选触发局部掩码翻转或 GF(2) 邻域效应 | 核形状 / XOR 邻域 | **ft09**（`maskflip` 已 WIN） |

> 2026-09-08 阶段 1.5：ft09 全关 WIN 的主导转移不落在上表前六项 → 补 **toggle**。实现见 `longquan/interactive/maskflip/`。详见 `docs/stage-1.5-reverse-coverage.md`。

## 2. 这个清单从哪来的（不是拍脑袋）

四个来源，交叉验证：

1. **Chollet ARC 原始论文的 core knowledge priors**：对象性、目标性、数量、基本几何、拓扑——这是他明说 ARC 测的东西。
2. **归纳逻辑编程解 ARC 的文献**（如 Sage 期刊那篇）：原语签名 `(Obj, Orientation, Direction, Len, NewColor, OutputObj)`，对应「对象、朝向、方向、长度、变色、输出对象」。
3. **人类解题轨迹的观察**：社区公开的高分解法，反推人用了哪些操作。
4. **引擎源码逆向（ARC-AGI-3 特有）**：读官方引擎 `step`/`on_action`/`next_level` 判定，标出每个游戏的真实主导机制。**这一来源是 E 族的来源，也是「前四族是否覆盖」的检验器。**

**诚实标注**：这个清单是「初版全集」，不是「最终全集」。它的完整性要等「用人类轨迹 + 开源求解器」做一次系统盘点来补。E 族尤其如此——它是探路后补的，边界还待「反向盘点」校准。

## 3. 「全」怎么验证（不靠背题）

一个原语库「全不全」，不能靠「把 25 款都解了」来验证（那是事后背题）。要靠**双向验证**：

- **正向**：从原理推出原语，确保五族（几何/拓扑/颜色/对称/交互）都有覆盖。
- **反向**：拿人类轨迹 + 引擎源码逆向 + 开源求解器，做「规则标注」，看每个游戏的真规则，能不能落到我们的原语里。落不进去的，就是缺的原语，补进去。

**这个「反向盘点」就是外部资料汲取的真正用法**——不是抄答案，是「用已解游戏，校准原语全集」。E 族就是反向盘点的一次落地：25 款里一批游戏落不进前四族，于是补出 E 族。

---

## 4. 落地顺序（务实，不贪多）

全集有 24 个原语，一次全实现不现实。分四批：

- **第一批（先证明能工作）**：reflect（已有，ar25 已验证）——1 个，有真实验证游戏、已收口。copy 的几何代码虽已写且正确，但 ls20 探路被源码逆向推翻（实为 move+match），copy 无真实验证游戏，撤回「未验证」。
- **第二批（补交互，追真实分布）**：move、mate、match——补 ARC-AGI-3 最常见的交互机制（m0r0、r11l、tr87、ls20 已标主导原语）。**toggle**（ft09）于 1.5 反向盘点补入，实现已有 `maskflip`。
- **第三批（补几何+拓扑+颜色）**：translate、recolor、rotate、scale、connect、fill——补「网格变换」余项。
- **第四批（补对称+模式+其余）**：symmetry、tiling、pattern、count、order、contain、overlap、shear、sequence、gravity、waypoint。

**每一批的验收**：不是「写了代码」，是「在原语库里，用这个原语解出一个真实游戏」。

**关键纪律（探路教训）**：**不要为一个原语硬凑验证游戏。** translate/recolor/copy 在 25 款里很可能没有「主导原语」的游戏（它们是辅助原语，如 ls20 的主导其实是 move+match，copy/recolor 只是场景铺设的视觉线索）。给一个不是该原语的游戏乱贴标签 = 造假，违背红线 2。没有真实验证游戏的原语，宁可留在「未验证」状态，也不造假。

---

## 5. 与原语选择器的关系

全集是「选择器的搜索空间」。选择器面对新游戏，在这 24 个原语里挑。所以：

- 全集不全 → 选择器天花板被锁死
- 全集全了，但每个原语实现有 bug → 选择器选对了也解不出

**两个都要对，缺一不可。** 第一版先攻「reflect 做扎实」，证明「原语 + 选择器」这个机制能工作；E 族（move/mate/match）是紧随其后的重头戏，因为那是 ARC-AGI-3 的真实规则重心。

---

## 6. 一句话

**原语全集 = 人类视觉认知 + 交互引擎的基本操作，分几何/拓扑/颜色/对称/交互五族，共 24 个。它靠「设计原理推出 + 人类轨迹反向盘点 + 引擎源码逆向」保证完整性，不靠背 25 款游戏。ARC-AGI-3 是交互引擎，不是网格变换题——所以 E 族（move/mate/match/sequence/gravity/waypoint/toggle）才是它的规则重心，而不是经典的 translate/recolor。**
