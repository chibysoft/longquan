# 龙泉以终为始施工图：从今天到 ft09 迁移报告

> 2026-09-05 · Longquan 龙泉 · 这是唯一需要照着走的图，其余七份文档是它的「宪法」依据
> 终点：**ft09 用闭卷模板拿到 ≥1 关正分 + 一份可审计的 `ft09_migration_report.md`**

---

## 0. 终点定义（以终为始的「终」）

**终点的硬证据（全部满足才算到）**：

1. `ft09` 在真实 scorecard 上 `levels_completed ≥ 1`（正分）
2. 求解路径**闭卷**：不读 ft09 引擎源码、不 import 罐头表
3. 产出 `ft09_migration_report.md`，含三样证据：
   - 原语选择轨迹（程序按序试了哪些原语、score 多少）
   - 失败证据与搜索收缩（每轮 retry 的 S→T_pred→T_actual 记录）
   - 锚点确认记录（每个恢复点被独立确认几次）
4. 全程步数 ≤ 单关预算（首试 1.5×、累计 2.5×）

**「终」的一句话**：不证明「程序学会了 ft09 的真规则」（不可证明），证明「程序经历了一个可审计的归纳过程，且在这个过程中拿到正分」。

---

## 1. 从终点倒推的五个阶段

```
阶段 0：地基（站 1 收尾）      —— 让 reflect 原语在 AR25 上 L1-L3 完整通关
阶段 1：原语库成形（站 2）     —— reflect + copy 两个原语 + 选择器，能「选对」而非「写死」
阶段 2：程序表示（站 2/3 之间）—— 规则 = 原语序列，能组合
阶段 3：结构归纳（站 3）       —— MDL 最短优先 + 约束求解
阶段 4：ft09 迁移 + 报告       —— 终点验收
```

每个阶段结束，都有一个「能证明什么」的明确答案。

## 2. 阶段 0：地基（reflect 补全，追平 M1）

**目标**：reflect 原语在 AR25 上 L1-L3 完整通关（现在只有 L1）。

**具体任务**（站 1 的三个缺口，已定位）：

1. 轴可动 + 负坐标：search 遍历轴的完整候选范围（含负坐标），cover 允许轴在棋盘外
2. 横轴真实帧识别：用「保存真实 L3 帧到 npy」离线调试，看清横轴/镜像的真实渲染
3. 反射镜像干扰：perceive 正确处理色4镜像（不把它当块）

**验收（能证明什么）**：`test_replay_ar25_l1_l3` 在本地 arcengine 回放通过（levels=3）。证明「单原语做扎实了」。

**⚠️ 回放载体（先做，否则验收无参照系）**：龙泉当前**没有** replay 测试（只有 test_loop.py 离线假回放）。阶段 0 第一步是**写一个独立回放脚本 + 黄金数据**：

1. 把 AR25 L1/L2/L3 的真实帧 + 正确动作序列固化下来（灵境版 `test_ar25_replay_engine.py` 可参考，它在 `Lingjing-Solo-/tests/` 里）
2. 本地 arcengine 回放这些黄金数据，确认 levels=3
3. 之后龙泉的求解器产出，就跟这份黄金数据比对，作为「回放通过」的参照系

**不做什么**：不追求 AR25 步数最优，不引入任何别的原语。

## 3. 阶段 1：原语库成形（第一批 reflect + copy + 选择器）

**目标**：从「写死 mirror」升级到「原语库 + 选择器」。

**具体任务**：

1. `hypotheses/mirror.py` → 改名 `hypotheses/reflect.py`，接口对齐 score/cover/backproject 三函数
2. 补 `hypotheses/copy.py` 的 cover/backproject（验证游戏 = ls20，已坐实，真实帧样本已固化进 `tests/fixtures/`）
3. 写 `hypotheses/registry.py`：原语注册表
4. loop 加「原语选择器」：按 score 排序，逐个试，回放淘汰

**验收（能证明什么）**：选择器能在一个「已知原语库」内，对 AR25 自动选对 reflect 原语并解出（而不是写死）。证明「选择」机制成立。

**关键约束**：每个原语要真的「能用它解一个真实游戏」，不是空壳。reflect 已经在 AR25 验证过；copy 用 ls20 验证。

**⚠️ 验证游戏的选择（已探路定案，见 docs/verify-games.md）**：探路 + 源码逆向 + 线上实测已得出结论——**copy → ls20（坐实，可派活）；recolor / translate 无「主导原语」的游戏**（recolor 原候选 m0r0 实为「移动配对」，translate 原候选 vc33 实为「重力点选」）。硬凑验证游戏 = 造假，违背红线 2。因此第一批只做 reflect + copy 两个有真实验证游戏的原语；recolor/translate 撤下，留待「原语全集扩充交互族」后再定。**交互族原语（move/mate/match）是 ARC-AGI-3 的真实规则重心，但 cover/backproject 接口语义待推进核定义后另行派活。**

## 3.5 阶段 1.5：原语库反向验证（求全的「被执行」）

**目标**：把「原语库完整性」从「我们觉得够用」变成「被真实游戏规则检验过确实够用」。

**为什么现在做**：阶段 1 跑通后，手上有 reflect（AR25）+ copy（ls20）共 2 份「真实游戏规则结构」的实际经验，加上探路逆向得到的交互族游戏（m0r0/r11l/tr87/vc33 等）的机制标注。正好做反向盘点，检验原语库（尤其新增的交互族）是否覆盖这些真实规则，也为阶段 2 的组合提供「原语边界是否清晰」的判断依据。

**具体任务**：

1. 从阶段 0/1 已解的游戏里，提取每个游戏的「规则结构」
2. 标注每个游戏的真规则对应哪个原语（含交互族 move/mate/match/sequence/gravity/waypoint）
3. 检查是否有「原语库未覆盖」的情况
4. 未覆盖 → 补原语后再继续；覆盖 → 进入阶段 2

**验收（能证明什么）**：当前原语库能覆盖所有已解游戏的真规则；若缺则补原语后再继续。证明「求全」被真实规则检验过，不是拍脑袋。

**注意**：这是 primitives-taxonomy.md §3「双向验证」的反向那半边，从「被论证」变成「被执行」。不跳——跳了，原语库的完整性就退化成「我觉得够用」。

## 4. 阶段 2：程序表示（规则 = 原语序列）

**目标**：规则不再「单个原语」，而是「可组合的原语序列」。

**具体任务**：

1. 定义「程序」数据结构：`[{"op": "reflect", "axis": "V", "coord": 10}, {"op": "translate", "dx": 2, "dy": 0}]`
2. 定义复杂度度量：复杂度 = 原语数量 + 参数位数
3. 定义「执行语义」：给定程序 + 输入帧，算出输出帧

**验收（能证明什么）**：一个两原语的程序（如 reflect→recolor），能在合成帧上正确执行。证明「组合」机制成立。

**注意**：这是「程序合成」的地基，但第一版只验证「单原语」，组合执行先跑通合成用例，不急着上真实游戏。

---

## 5. 阶段 3：结构归纳（MDL 最短优先 + 约束求解）

**目标**：程序合成——按复杂度从小到大搜程序，用样例淘汰。

**具体任务**：

1. 最短优先搜索：在「程序空间」按复杂度从小到大枚举
2. 约束求解：候选程序 vs 已知样例，不符淘汰
3. 接升级重试：失败证据 → 收缩搜索空间 → 找下一个最优（见 retry-loop.md）
4. 接步数预算：首试 1.5×、累计 2.5×（见 step-budget.md）

**验收（能证明什么）**：给一组合成样例，程序能「从空开始」归纳出正确的最小程序。证明「归纳」机制成立（在合成域）。

**⚠️ 合成测试集（先造好，不边做边造）**：阶段 3 开始前，先准备一个固定的合成测试集——用几个已知规则的程序（如 `reflect→recolor`、`translate→copy`）**反向生成**一批输入→输出样例对。这些样例对作为「黄金测试集」，程序从空开始归纳，看能否复现出正确的最小程序。测试集要包含：单原语样例（各原语一个）、两原语组合样例（组合的 2-3 个）。**不做边做边造，否则无法判断「归纳对了没有」。

## 6. 阶段 4：ft09 迁移 + 报告（终点）

**目标**：把阶段 0-3 的全部能力，在 ft09 上真实跑通。

**具体任务**：

1. ft09 探路：拉真实帧，搞清「画面长什么样、动作是什么」（纯观测，不读源码）
2. 用原语库 + 选择器 + 程序合成，在 ft09 上求解
3. 升级重试 + 步数预算约束下，拿 ≥1 关正分
4. 全程记录，产出 `ft09_migration_report.md`

**验收（终点的硬证据，见 §0）**：真实 scorecard levels≥1 + 闭卷 + 三样证据报告 + 步数合规。

---

## 7. 每个阶段的「不做什么」（防滑回背题）

- 阶段 0：不追求 AR25 步数最优
- 阶段 1：不为凑原语数写空壳，每个都要真能解一个游戏
- 阶段 2：不急着上真实游戏，合成用例跑通即可
- 阶段 3：不在真实 ft09 上调试，合成域跑通再迁移
- 阶段 4：不读 ft09 源码，不 import 罐头，不把「碰巧通过」当「已验证」
