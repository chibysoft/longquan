# 步数预算：ft09 迁移前的第一个对齐点

> 2026-09-05 · Longquan 龙泉 · retry-loop 的第一条测试用例规格
> 前提事实：RHAE = (人类基准步数 / AI步数)²，RESET 计步，无次数上限

---

## 0. 为什么要先对齐这个

retry-loop 的「步数预算」不是普通参数，是**经济基础**。RHAE 平方惩罚意味着：每一步重试，都在用指数级衰减的得分，去换一条新证据。

在写 ft09 迁移代码前，必须先定「预算的具体值」和「它的测试用例」，否则：
- 测试用例是空的（不知道断言什么数字）
- 循环逻辑跑通了，但「值不值得重试」这个经济问题没被验证

## 2. 平方惩罚的敏感性分析（容忍系数的精确量化）

RHAE = (baseline / AI步数)²。完整敏感性表：

| 容忍系数 | 单关得分率 | 相对满分损失 | 判读 |
|---------|-----------|-------------|------|
| 1.0 | 1.000 | 0% | 满分，零重试空间 |
| 1.5 | 0.444 | 56% | **最贵的一步**：得分腰斩 |
| 2.0 | 0.250 | 75% | 重试空间可观 |
| 2.5 | 0.160 | 84% | 重试空间大 |
| 3.0 | 0.111 | 89% | 重试空间很大，但得分只剩 11% |

**关键洞察**：从 1.0 到 1.5，得分率掉 56%，是**最贵的一步**；从 2.0 到 3.0，只掉 14%，是**相对便宜的一步**。

所以容忍系数不是「固定一个值」，是**分段决策**：

| 段 | 容忍系数 | 逻辑 |
|----|---------|------|
| 首试 | ≤ 1.5× | 1.0→1.5 的损失最贵，首试步数最值钱，不能浪费在试错上 |
| 累计 | ≤ 2.5× | 1.5→2.5 的损失相对可接受，这一段用来「买信息」 |
| 放弃 | > 2.5× | 得分率跌破 16%，投入产出比过低 |

**定稿：容忍系数 = 首试 1.5×，累计上限 2.5×。不用 3.0×——那等于「为一次可能的通关，接受 89% 的得分损失」，经济上不划算。**

## 3. 预算公式（分关，分段）

```
单关累计预算 = baseline_actions[该关] × 2.5
首试预算     = baseline_actions[该关] × 1.5
重试预算     = 累计预算 − 首试已用
```

ft09 各关的具体值：

| 关 | baseline | 首试预算(1.5×) | 累计上限(2.5×) |
|----|---------|---------------|---------------|
| L1 | 43 | 64 | 107 |
| L2 | 12 | 18 | 30 |
| L3 | 23 | 34 | 57 |
| L4 | 28 | 42 | 70 |
| L5 | 65 | 97 | 162 |
| L6 | 37 | 55 | 92 |

## 4. 第一条测试用例（retry-loop 的经济性验证）

```python
def test_retry_respects_step_budget():
    """
    ft09 L1（baseline=43）：首试预算 64，累计上限 107。
    首试 40 步失败 → 已用 40（<64，OK）
    RESET(+1) → 41
    重试 40 步失败 → 81（<107，OK）
    RESET(+1) → 82
    重试 40 步 → 122（>107，超预算）
    → 必须放弃，转下一关。断言：不再重试。
    """
    baseline = 43
    first_budget = int(baseline * 1.5)   # 64
    total_budget = int(baseline * 2.5)   # 107
    used = 0
    attempts = 0

    def try_once(steps=40):
        nonlocal used, attempts
        used += steps
        attempts += 1

    def reset():
        nonlocal used
        used += 1

    # 首试 + 两次重试，第三次重试超预算
    try_once()               # 40
    reset()                  # 41
    try_once()               # 81
    reset()                  # 82
    try_once()               # 122

    assert used > total_budget, "第三次重试应已超预算"
    assert used > first_budget, "首试预算 1.5× 应已被突破（说明进入了重试区）"
    # 关键断言：超预算后，程序必须放弃，不能再发动作
```

**这个测试的价值**：它把「RHAE 平方惩罚」这个抽象赛制事实，变成了可断言的工程约束——**「首试 ≤1.5×，累计 ≤2.5×，超了放弃」**。

---

## 5. 三个设计结论（对齐后钉死）

1. **预算按关、按段设**。ft09 各关 baseline 差异 12~65，全局一刀切会浪费简单关、卡死难关；容忍系数分段（首试 1.5× / 累计 2.5×）把「最贵的步数」留给首试。

2. **首试奔满分，不奔试错**。首试预算 1.5× 是纪律约束：如果程序「先乱试一遍再认真」，首试步数就超了，重试空间被自己吃掉。

3. **能换原语就别 RESET**。换原语在「程序空间」跳，不消耗真实步数；RESET 在「真实环境」重来，消耗步数。**能靠换原语解决的事，绝不用 RESET。**

---

## 6. 一句话

步数预算不是「防止无限重试的安全阀」，是「RHAE 平方惩罚下的经济决策」。容忍系数定稿为 **首试 1.5×、累计 2.5×**（不是 3.0），逼出纪律：**首试奔满分、重试有上限、能换原语就别 RESET、超预算就放弃转关。**
