# ls20 L3 hline 传送门发现（E2 合成探针）

> 脚本：`tools/ls20_l3_hline_second_gate_probe.py`
> 性质：设计期探路（最小动作 + 比对 levels），非运行时求解器

---

## 0. 结论（一句话）

**hline 不是武装触发点，而是纵向传送门**：mover 站 hline 正下方 `(10,1)`，发 DOWN，
一步从像素 `(54,5)` 跳 40px 到 `(54,45)` = 逻辑格 `(10,9)`（stamp 门前）。
这彻底推翻了「下半区能量不可达」——**能量瓶颈从来不存在，hline 是直通下半区的下行通道。**

武装判据仍是未知量：传送后 stamp 门 `(10,10)` 的色9 仍挡。

---

## 1. 传送门证据（决定性）

| 步 | 动作 | mover 像素 bbox | 逻辑格 | layers |
|----|------|----------------|--------|--------|
| A21 | UP | `(54,5,58,6)` | `(10,1)` = hline 正下方 | **17** |
| B1 | DOWN | `(54,45,58,46)` | `(10,9)` = stamp 门前 | **6** |
| B2 | DOWN | `(54,45,58,46)` | 未动（色9 挡） | 6 |

- **B1 的一步 DOWN 跳了 8 格（40px）**。普通移动是 5px/步，这不可能是步进，只能是传送。
- hline `(54,4)-(58,4)` 与 mover `(10,1)` 的 footprint `(54,5)-(58,6)` **x 完全对齐**，
  纵向相邻（mover 在 hline 正下方）。
- `(10,1)` 是**唯一** x 对齐 hline 正下方的 walkable 格（离线核实：`cells directly below hline = [(10,1)]`）。
- 落点 `(10,9)` = 同列向下，stamp 块 `(53,49)-(59,55)` 的正上方 walkable 格。

**layers 签名**（引擎多层 flash，标记特殊位置）：
- `layers=17`：mover 站 hline 正下方 `(10,1)` 时。
- `layers=6`：stamp 门前 `(10,9)` 及撞 stamp 门时（与 E1 的 post9 撞门 `layers=6` 一致）。

这两个非 1 的 layers 值是「门/传送」的渲染签名，与软重置（layers 变多 + c11 归零）不同。

## 2. 与已有传送门的对比

| 传送门 | 签名 | 方向 | 状态 |
|--------|------|------|------|
| `(1,1)→(6,1)` | 色1 vline 在左 + 色4 墙 | 横向 | 已建模（`detect_warps`） |
| `(10,1)→(10,9)` | 色1 hline 在上 + x 对齐 | **纵向** | **已建模（`detect_warps` 本轮补上）** |

`detect_warps` 现已检测两类传送门（均从帧特征推导，非硬编码坐标）：

- **横向**：footprint 西侧色1 竖条（vline）+ 同行向右连续 run → 全方向传送到 run 最右。
- **纵向**：footprint 正上方色1 **横向条**（hline，≥2 像素以拒绝 vline/plus 单点）
  → **仅 DOWN** 传送到同列向下连续 run 的最下端（stamp 门前 `(10,9)`）。

落点规则与横向完全对称（「同列向下 run 最下端」= 被 armed-only 的 `(10,10)` 截断处）。
离线验证：L1/L2 空，L3 精确 5 个 warp key（横向 4 方向 + 纵向 DOWN），无假阳性。

## 3. 对 L3 布局语义的改写

旧理解（错）：起点 → 上半区接触/补给 → 能量不够下不到下半区 → 卡死。

新理解（对）：

```
起点 (1,8) 左上
   │
   ├─ 上半区：补给0(6,3) / 补给1(3,6) / plus 标记(9,2) / 横向传送门(1,1)→(6,1)
   │
   └─ hline 纵向传送门 (10,1) → DOWN → (10,9) stamp 门前
                                          │
                                          └─ stamp 门 (10,10)：色9 内嵌图案 C 挡，需「武装」
```

hline 在 x=54-58，stamp 块在 x=53-59 —— **x 对齐不是巧合**，hline 就是 stamp 块的
「下行入口」。引擎用色1 横向条做了一个「从天而降」的下行通道。

## 4. 武装判据：仍是未知量

本轮已排除了「hline 相邻武装」（hline 相邻后 c1 结构零变化，传送后 stamp 门色9 仍挡）。
结合前几轮，武装候选已排除 4 条：

| 候选 | 状态 |
|------|------|
| plus 重叠（H19 ± H23） | ❌ C1/C2 |
| interact（ACTION5） | ❌ E1 |
| hline 相邻 | ❌ E2（是传送门，非武装） |
| 第二块 STATIC 可动 | ❌ 线上 19 步不动 |

**下一步必须先把 hline 纵向传送门建模进 `detect_warps`**，然后重新审视：
传送把 mover 送到 stamp 门前 `(10,9)`，之后要「武装」才能进 `(10,10)`。武装触发
可能藏在「传送过程」或「stamp 门前的特定动作」里——而这两处都**从未被独立探测**。

## 5. 纪律核对

- 不背题：路径由 BFS 从帧生成；hline 传送门是线上实测发现，非罐头表。
- 不读源码：运行时只吃帧；layers/c1/c9 均从帧提取。
- 不以像素当通过：判定只看 `levels_completed`；传送门判定用「一步跳 8 格 + layers 签名」双证据。
